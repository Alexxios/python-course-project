    Developer quickstart

    The selected final-project theme is Учебная платформа. The business API and interactive documentation are versioned under /v1. Earlier homework solutions remain on the ASSIGNMENT-4 and ASSIGNMENT-6 branches.

    Local development

    Install Python 3.14+, uv and Just, then run from the repository root:

    uv tool install rust-just
just bootstrap
uv run pre-commit install
uv run --package app python -m app init-db
uv run --package app python -m app create-admin --username admin --first-name Admin --last-name User
uv run --package app uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload --reload-dir services/app/src

    The administrator command prompts for a password of 12 to 128 characters. No default administrator is created. Open http://127.0.0.1:8000/v1/docs, call POST /v1/auth/login with your username and password, and paste the returned access token into Authorize. Use the administration endpoints to create a course, its ordered lessons, and test questions, then publish the course.

    Register a separate student with POST /v1/auth/register, log in as that student, enroll in a published course, and progress through its lessons. The API guide describes every endpoint and the grading rules.

    The default database is learning.sqlite3 relative to the current working directory. It is excluded from Git and Docker build contexts. The application does not create tables on startup: run init-db before serving requests. The command applies packaged Alembic migrations and is safe to repeat.

    To choose an absolute SQLite path or PostgreSQL, export DATABASE_URL before running both the migration and the server:

    export DATABASE_URL=sqlite:////absolute/existing/directory/learning.sqlite3
# Or connect to your PostgreSQL database:
# export DATABASE_URL=postgresql+psycopg://app:app@127.0.0.1:5432/app
uv run --package app python -m app init-db

    The SQLite parent directory must exist. CLI/server settings come from process environment variables; .env is used by Docker Compose, not loaded implicitly by the Python application. just bootstrap creates .env from .env.example only when it is missing.

    Docker Compose

    Start Docker Engine or Docker Desktop, then run from the workspace root:

    just bootstrap
docker compose --env-file .env -f infra/docker-compose.yml -f infra/docker-compose.dev.yml up --build -d api
docker compose --env-file .env -f infra/docker-compose.yml -f infra/docker-compose.dev.yml ps -a
docker compose --env-file .env -f infra/docker-compose.yml -f infra/docker-compose.dev.yml exec api \
  uv run --no-sync python -m app create-admin --username admin --first-name Admin --last-name User

    infra/docker-compose.dev.yml adds the API and migration service to the shared infrastructure in infra/docker-compose.yml. The command builds the existing service Dockerfile, starts postgres, waits for database health, runs migrations, and starts the API. The migration container exits successfully after applying the schema. PostgreSQL is also available on 127.0.0.1:5432 for host development; set POSTGRES_PORT in .env to change that port. The API binds to 127.0.0.1:8000 by default; set APP_PORT to change its port. Database data persists in the shared postgres-data volume.

    POSTGRES_DB, POSTGRES_USER, and POSTGRES_PASSWORD default to app for local development. Override them in .env before the first startup. Use URL-safe credentials (letters, digits, _, -) with this local Compose template, which interpolates them into the connection URL. Omit the final api from the startup command to include Redis, Prometheus, and Grafana in the same stack. See infra/README.md for connection and monitoring settings, and for notes on data from the previous root Compose stack.

    Inspect logs or stop the combined stack with the same Compose files:

    docker compose --env-file .env -f infra/docker-compose.yml -f infra/docker-compose.dev.yml logs api migrate
docker compose --env-file .env -f infra/docker-compose.yml -f infra/docker-compose.dev.yml down

    The database volume is retained when the stack is stopped.

    Check the service

    curl --fail http://127.0.0.1:8000/health/live
curl --fail http://127.0.0.1:8000/health/ready
curl --fail http://127.0.0.1:8000/v1/courses
just check

    Liveness reports whether the app can respond. Readiness checks the lifecycle and database schema access, returning 503 before migration or during a database outage. The catalog initially contains no courses.

    just check validates generated documentation, builds MkDocs, runs Ruff, and executes pytest in isolated member environments. Each scope emits coverage, JUnit, and Allure artifacts under reports/. just check services/app checks only the API service. Start Docker before running the app's integration tests; Testcontainers manages a disposable PostgreSQL container using the same image as infra/docker-compose.yml. See tests for integration and fuzz runs.

    Daily workflow

    just format
just check

    Keep runtime version bounds in the root pyproject.toml. Declare dependency names and extras without bounds in consuming members, and commit the shared uv.lock alongside manifest changes. Edit templates/readme/*.jinja for the generated workspace README and run just codegen.

    just new-service <name> and just new-lib <name> still scaffold workspace members. App unit tests live in services/app/tests/unit/; API and database tests live in services/app/tests/integration/ and use PostgreSQL Testcontainers. just docs, just serve, and just reports retain the existing documentation and reporting workflows. See Development tools and CI reports for the shared tooling.
